# VERDANTIS — MVP Specification

**Project:** Verdantis — AI-Powered Plant Care Management System
**Approach:** Pure ML/DL (software-only). No IoT, no sensors, no hardware dependency.

---

## 1. MVP Definition

The Minimum Viable Product is a web application that lets any user, with only a
photograph and a browser, (a) identify a plant, (b) diagnose visible disease,
(c) ask free-form plant-care questions, and (d) receive schedule and species
recommendations generated by deterministic scoring over a curated botanical
dataset.

### 1.1 MVP Success Criteria

| # | Criterion | Measure | Status |
|---|-----------|---------|--------|
| 1 | Identify a plant from an image | Structured species report returned | Done |
| 2 | Diagnose a diseased leaf from an image | Diagnosis + treatment plan returned | Done |
| 3 | Hold a multi-turn care conversation | Context retained across turns | Done |
| 4 | Species recommendations for an environment | Top-6 ranked with match score | Done |
| 5 | Prioritised maintenance schedule | Today / week / month buckets | Done |
| 6 | Numeric health prediction for a collection | 0–100 score + category + advice | Done |
| 7 | Secured accounts | Email auth, leaked-password protection on | Done |
| 8 | No hardware dependency | Zero sensor/IoT code paths | Done |

## 2. In-Scope MVP Features

### F1 — Plant Identification (Computer Vision)
Image upload → base64 encode → multimodal vision inference → markdown report with
common name, scientific name, identifying features, native habitat, care basics.

### F2 — Disease Detection (Computer Vision)
Image of the affected region → visual anomaly reasoning → disease class, severity
(mild / moderate / severe), cause, treatment protocol, prevention guidance.

### F3 — AI Plant Assistant (NLP)
Chat interface over a transformer LLM with a horticulture system prompt and full
conversation history passed each turn for contextual continuity.

### F4 — Care Recommendations
Species name → watering, light, humidity, soil, fertilising, repotting and
seasonal-adjustment guide.

### F5 — Dashboard (Health Estimation)
Weighted multi-factor scoring across watering lateness, fertilising lateness and
issue severity; renders collection score, per-plant cards and urgent alerts.

### F6 — Smart Suggestions (Similarity Matching)
User sets temperature, humidity and light level; season auto-detected. A Gaussian
kernel plus categorical similarity ranks the dataset and returns the best 6 matches.

### F7 — Maintenance Scheduler
Urgency scores feed a priority queue bucketed into Today / This Week / This
Month, deduplicated and sorted by urgency.

## 3. Explicitly Out of MVP Scope

- Hardware sensors, real-time telemetry (permanently excluded).
- Native mobile apps, offline model execution, AR overlay.
- Marketplace / e-commerce, social feed, expert verification workflow.
- Custom model training on a self-collected regional dataset.
- Multi-language UI.

## 6. Acceptance Tests (MVP gate)

1. Upload a leaf photo on Identify → non-empty species report within ~5 s.
2. Upload a blighted leaf on Disease → diagnosis names a disease class and a treatment.
3. Ask two dependent questions in Assistant → second answer references the first.
4. Move the temperature slider on Suggestions → ranking order changes.
5. Dashboard health score stays inside 0–100 for every synthetic input.
6. Maintenance never lists the same task in two buckets.
7. Gateway failure (402/403/429) surfaces a visible, specific error — never a silent fallback.

## 7. Non-Functional Targets

| Attribute | Target |
|-----------|--------|
| Vision inference latency | ≤ 4 s p95 |
| Chat first token | ≤ 2 s p95 |
| Local scoring | < 100 ms |
| Bundle | Code-split per route |
| Accessibility | Semantic HTML, alt text, keyboard reachable |
| Security | RLS on every public table, server-side keys only |

---

## 8. Risks and Mitigations

| Risk | Mitigation |
|------|-----------|
| Vision misclassification on poor photos | Prompt requests confidence and a better photo |
| AI credit exhaustion (402) | Surface owner-facing message, halt background work |
| Rate limiting (429) | Bounded backoff honouring `Retry-After` |
| Hallucinated botanical facts | Lexical grounding over the curated dataset |
| Dataset breadth | Documented as future scope: regional fine-tuning |

---

## 9. Honesty Statement

All vision and language inference is zero-shot against a pretrained third-party
multimodal model. No in-house model training or image dataset collection has been
performed, and no held-out accuracy has been measured. Health, ranking and
scheduling modules are deterministic rule-based scoring functions, not learned models.
